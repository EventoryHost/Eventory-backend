FRONTEND INTEGRATION GUIDE - ANONYMOUS CHAT (WEBSOCKETS)

We are using WebSockets for real-time communication. Polling is NOT required for new messages.

1. Initialization Flow
   a. Check Status: `GET /api/anon-chats/:anon_customer_id/status`
      - If status is "ACTIVE", you get a `chat_id`.
      - If status is "NONE" or "FINISHED", you do NOT have a `chat_id` yet.

   b. First Message (Start Chat):
      - If you have NO `chat_id`:
        - Call `POST /api/anon-chats/message` (REST) to send the first message.
        - This creates the chat and returns `{ chat_id: "...", ... }`.
        - Store this `chat_id`.

   c. Connect WebSocket:
      - Connect to the socket server (same URL as API).
      - Emit `join_chat` event:
        ```javascript
        socket.emit("join_chat", {
          chat_id: "CHAT_ID_FROM_STEP_A_OR_B",
          sender: "anonymous_customer",
          chat_type: "anon_customer-admin"
        });
        ```

2. Sending Messages (Subsequent)
   - Once you have `chat_id` and have joined the room, send messages via WebSocket:
     ```javascript
     socket.emit("send_message", {
       chat_id: "CURRENT_CHAT_ID",
       chat_type: "anon_customer-admin",
       sender: "anonymous_customer",
       sender_id: "ANON_CUSTOMER_ID",
       message_content: "Hello world",
       message_type: "text" // or "image", "file", etc.
     }, (error, response) => {
       if (error) console.error(error);
       else console.log("Message sent", response);
     });
     ```

3. Receiving Messages
   - Listen for `new_message` event:
     ```javascript
     socket.on("new_message", (message) => {
       // message object contains:
       // _id, message_content, sender, message_type, etc.
       // Check if message.chat_id matches current chat
       if (message.chat_id === currentChatId) {
         // Add to UI
       }
     });
     ```

4. File Uploads
   - Use `POST /api/chats/upload-media` (REST) to upload file.
   - Get `attachment_url` from response.
   - Send WebSocket message with `message_type: "image"` (or "file") and `attachment_url`.

5. Vendor Cards
   - Backend sends `message_type: "vendor_card"`.
   - `message_content` will contain the JSON stringified card data (until metadata field is added).
   - Parse `message_content` to render the card.
